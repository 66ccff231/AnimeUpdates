# 日漫每日更新表

看**日本动画**每天更新什么。Windows 桌面程序，双击就开。

**数据源是 [AniList](https://anilist.co/)（日本动画的全球数据库）。**
播出时间来自各动画官方公布的在播日程，精确到分钟，还带第几话、评分、制作公司、
可看的流媒体平台。

## 三种启动方式

| 方式 | 怎么启动 | 特点 |
| --- | --- | --- |
| **双击 exe（推荐）** | `日漫每日更新表\日漫每日更新表.exe` | 图标和名字全对，**不需要装 Python**；首次启动 1.1 秒，之后 0.2 秒 |
| 开发时运行 | 双击 `日漫每日更新表.bat` | 直接跑 `.py`，改完代码立刻生效（需要 Python） |
| 命令行 | `python jp_anime_daily_gui.py` | 同上，可以加 `--no-fetch` 等参数 |

## 界面与操作

- **顶部横幅**：品牌紫→青渐变，左边标题，右边大字「今天 5 部更新」和「下一部 …／播出时刻与倒计时」
- **工具栏卡片**：实心品牌色的「⟳ 刷新」、范围（今天／3／7／14／30 天）、类型、最低评分、搜索框、以及「只看已播出」开关（开启时按钮变实心，一眼能看出筛选开着）
- **表格**：按日期分组、今天整组粉色高亮、隔行浅底纹、鼠标悬停整行高亮；灰色=已播出，橙色=待播出
- **两列标题**：「番剧名（中文）」为主，「原名（日文）」对照；搜索时两列都能命中
- **状态栏**：数据源、条目数、抓取时间、当前范围；选中某行时显示该行的完整信息
- **深色模式**：视图 → 深色模式，选择会被记住
- **菜单栏**：文件（刷新／导出 CSV／打开数据文件夹／更新番剧中文名库／退出）、视图（范围、只看已播、深色模式、清空搜索、默认排序）、帮助（快捷键、AniList 官网、关于）

界面是自己画的一套配色（换成 ttk 的 `clam` 主题再定义样式），不依赖任何第三方 UI 库。
`jp_anime_daily_gui.py` 里的 `LIGHT` / `DARK` 两个字典就是全部颜色，想改配色只改那里。

| 操作 | 效果 |
| --- | --- |
| 双击某一行 | 浏览器打开 AniList 详情页 |
| 右键某一行 | 打开详情／去 bgm.tv 查中文名／复制番剧名／复制链接 |
| 点表头 | 按该列排序，再点一次反向 |
| 搜索框 | 即时筛选：日文原名、罗马音、英文名、制作公司都能搜 |
| `F5` / `Ctrl+F` / `Esc` | 刷新 / 聚焦搜索 / 清空搜索 |

导出的 CSV 是 `utf-8-sig` 编码，Excel 双击直接打开不乱码，内容就是**当前筛选后**能看到的东西。

## 关于图标

| 位置 | 显示什么 |
| --- | --- |
| 资源管理器里双击的那个 exe | ✅ 我们的图标（exe 自带图标资源） |
| 任务栏按钮 | ✅ 我们的图标 + 名字「日漫每日更新表.exe」 |
| 窗口标题栏 / Alt-Tab | ✅ 我们的图标 |

这就是打包成 exe 的意义：不打包时程序跑在 `pythonw.exe` 里，Windows 会把任务栏按钮命名成
**「Python」**、图标也用 Python 的，程序内部改不了。

> 顺带一提：**`.bat` 文件的图标永远改不了**。`.bat`/`.cmd` 格式没有地方存图标资源，
> Windows 画它时固定用系统内置的批处理图标，只能靠 exe 或快捷方式绕开。

`app.ico` 是程序自己生成的：纯标准库手写 ICO 格式（BITMAPINFOHEADER + BGRA + AND 掩码，
6 个尺寸从 16 到 256），没有用 Pillow。删掉会自动重建。
想换图标就改 `jp_anime_daily_gui.py` 里的 `_icon_sample()`——逐个像素决定颜色的那个函数。

## 数据存在哪

| 运行方式 | 缓存与设置位置 |
| --- | --- |
| exe 版 | `日漫每日更新表\data\`、`日漫每日更新表\gui_config.json`（跟着 exe 走，整个文件夹拷到别的电脑也能用） |
| `.py` 版 | 项目根目录的 `data\`、`gui_config.json` |

程序会记住窗口大小、位置、深色模式和筛选条件（范围／类型／最低评分／只看已播出）。

> 小细节：`gui_config.json` 是给人改的，所以读取时兼容带 BOM 的 UTF-8——用记事本保存过
> 也不会导致设置全部丢失（带 BOM 的 JSON 用普通 utf-8 读会直接抛异常，设置就静默失效了）。
如果上次是在副屏、或者显示器拔了导致位置跑到屏幕外，会自动回到屏幕中央。

## 重新打包 exe

```bat
python build_exe.py
```

产物在 `日漫每日更新表\`（单个 exe 2.28 MB，整包约 26 MB）。
依赖被删掉的话脚本会先自动下载。

两个注意点：

1. **这台机器的 pip 用不了**——它要往系统临时目录写文件，会被文件沙箱拦住（报 Errno 13）。
   所以 `_getdeps.py` 是直接从 PyPI 下载 wheel 再解包的（wheel 本身就是 zip），全程只写工作区。
2. pip 的默认源被配置成了清华镜像，而那个镜像在这台机器上连不通，脚本里显式指定了官方 PyPI。

## 为什么用起来不卡

- 启动先用 `data/` 里的缓存秒开，同时后台联网更新，不用干等
- 抓取跑在后台线程里，界面全程可点
- 子线程**完全不碰**界面控件：结果丢进 `queue`，主线程每 150ms 取一次
  （tkinter 不是线程安全的，跨线程操作控件会随机崩溃）
- 改「范围」时先用现有数据即时重排，再自动联网补齐缺的那几天

## 命令行版（可选）

`jp_anime_daily.py` 是数据层 + 终端表格版，桌面版直接 `import` 它复用抓取逻辑，
所以两个版本的数据完全一致：

| 参数 | 说明 |
| --- | --- |
| `--today` / `--days 7` | 只看今天 / 从今天起往后 7 天 |
| `--before 3` / `--after 3` | 今天往前／往后几天（默认都是 3） |
| `--min-score 75` | 只看 AniList 评分 ≥75 的（0–100） |
| `--type TV` | 只看某种格式：`TV` / `MOVIE` / `OVA` / `ONA` / `SPECIAL` |
| `--tz 8` | 显示用哪个时区，默认本机时区 |
| `--all-countries` | 不限日本，把中韩美动画也算进来 |
| `--adult` | 包含成人向条目（默认过滤掉） |
| `--offline` | 不联网，用 `data/` 里的缓存 |

## 关于时间

界面和终端都同时给出**本地时间**和**日本时间（JST）**。
动画的播出时刻永远以 JST 为准，比如「23:00 JST」在北京时间就是 22:00。

## 关于中文名

AniList 本身只有日文原名、罗马音、英文名，**没有中文名**。中文名来自
[bangumi-data](https://github.com/bangumi-data/bangumi-data)——一个开源动画数据集，
条目里同时带 `aniList` / `mal` / `bangumi` 的 id 和 `zh-Hans` 译名，
所以可以**按 id 精确匹配**，不用靠标题去猜。

匹配顺序：`aniList id` → `mal id` → 精确标题 → 去季数后缀 → 前缀模糊。
当前索引覆盖约 **83%**，匹配不到的条目自动回退显示日文原名
（比如 `mofusand` 这种数据集没收录的儿童番／短篇外传）。
界面上中文名和日文原名各占一列，搜索两列都能命中，右键也能分别复制。

新番播出后数据集会持续收录，过一段时间更新一次即可：

- **界面里**：文件 → 更新番剧中文名库（下载约 7MB），完成后会自动重新匹配
- **命令行**：`python update_titles.py`

索引文件是 `titles_zh.json`（约 1.5 MB），已随仓库提供，所以拿到就能直接用中文名。
原因说明：`api.bgm.tv`（Bangumi 官方 API）在国内网络下经常连不通，所以这里用的是
静态数据集而不是实时查询；代价是需要偶尔手动更新一次。

## 备注

- AniList 的公共 API 有限速（正常 90 次/分钟，紧张时会降到 30）。程序翻页之间会停
  0.7 秒，遇到 429/400 会自动退避重试最多 4 次。
- 抓一周大约 2～3 页、100 条记录，一两秒就好。
- 接口自报的 `pageInfo.total` 数不准（会说 5000），所以程序只显示实际抓到的条数。
- 只统计**日本动画**（`countryOfOrigin == JP`），默认过滤成人向条目。
